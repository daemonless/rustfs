## Deployment

### Podman Compose

```yaml
services:
  rustfs:
    image: "ghcr.io/daemonless/rustfs:latest"
    container_name: rustfs
    environment:
      - PUID=1000  # User ID for the application process
      - PGID=1000  # Group ID for the application process
      - TZ=UTC  # Timezone for the container
      - RUSTFS_ACCESS_KEY=${RUSTFS_ACCESS_KEY:-admin}  # Root S3 access key and Web Console sign-in username
      - RUSTFS_SECRET_KEY=${RUSTFS_SECRET_KEY}  # Root S3 secret key and Web Console password (generated into /config/secrets.env if unset)
      # - RUSTFS_SERVER_DOMAINS=  # Comma-separated domain names for virtual-hosted-style S3 requests, e.g. s3.example.com
      # - RUSTFS_REGION=  # S3 region reported to clients
      # - RUSTFS_VOLUMES=  # Space-separated data directories or distributed cluster endpoints
      # - RUSTFS_ARGS=  # Additional command-line arguments passed to rustfs server
    volumes:
      - "/containers/rustfs:/config"
      - "/containers/rustfs/data:/data"
    ports:
      - "9001:9001"
      - "9000:9000"
    # always (not unless-stopped) so FreeBSD's podman rc.d auto-starts it at boot
    restart: always
```

Save as `compose.yaml`, then run `podman-compose up -d`.

```yaml
    options:
      - container: 'args:--pull'
      - expose: '9001:9001 proto:tcp'
      - expose: '9000:9000 proto:tcp'
    oci:
      user: root
      environment:
        - PUID: !ENV '${PUID}'
        - PGID: !ENV '${PGID}'
        - TZ: !ENV '${TZ}'
        - RUSTFS_ACCESS_KEY: !ENV '${RUSTFS_ACCESS_KEY}'
        - RUSTFS_SECRET_KEY: !ENV '${RUSTFS_SECRET_KEY}'
    volumes:
      - rustfs: /config
      - rustfs_data: /data
volumes:
  rustfs:
    device: '/containers/rustfs'
  rustfs_data:
    device: '/containers/rustfs/data'
```

**Makejail**:

```
# Makejail

ARG tag=latest

OPTION container=boot
OPTION overwrite=force
OPTION from=ghcr.io/daemonless/rustfs:${tag}
```

Save the files above, then run `appjail-director up`.


> [!WARNING]
> Exposing ports in AppJail means that your service can be reached from remote hosts. If that is not your intention, do not expose the ports and communicate with the service using the jail's IPv4 address or hostname assigned by the virtual network.
>
> To avoid exposing ports, just remove the `expose` option in your `appjail-director.yml` or from your command-line arguments.

## Credentials and Web Console

Open the Web Console on port **9001** (`http://<your-host>:9001`).

If `RUSTFS_SECRET_KEY` is not set at first boot, the launcher generates a
random root secret key and saves it in `/config/secrets.env` (mode `0600`)
so the container never runs with upstream's public `rustfsadmin` default.
Read `/config/secrets.env` inside the container or host volume to view the
generated credentials, or set `RUSTFS_ACCESS_KEY` and `RUSTFS_SECRET_KEY`
explicitly before first start.

## S3 API clients

Point S3 clients at port **9000** (`http://<your-host>:9000`). Without
`RUSTFS_SERVER_DOMAINS`, configure clients for path-style addressing
(`force_path_style = true` / `--endpoint-url`). Set `RUSTFS_SERVER_DOMAINS`
when routing virtual-hosted bucket subdomains (`<bucket>.s3.example.com`)
through a reverse proxy.

## FreeBSD notes

Both listeners default to `0.0.0.0` (`0.0.0.0:9000` and `0.0.0.0:9001`)
rather than `:9000` / `[::]:9000` because FreeBSD sets
`net.inet6.ip6.v6only=1` by default.


**Architectures:** amd64, aarch64
**User:** `bsd` (UID/GID via PUID/PGID, defaults to 1000:1000)
**Base:** FreeBSD 15.1
